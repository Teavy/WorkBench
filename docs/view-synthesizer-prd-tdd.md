# View Synthesizer — PRD + TDD

> 基线日期：2026-10-03。本文将 PR 理解为产品需求（PRD），与技术设计（TDD）合并记录。`已实现`表示当前代码具备该行为，不等于生成质量或所有浏览器场景已得到保证。

## 1. 定位与边界（PRD）

View Synthesizer 是 Codex Workbench 中独立的“参考图转换视角”工具。用户上传一张图、选择内容类型和目标镜位，网页建立本地任务；用户随后在当前 Codex 对话中说“生成最新视角”，由 Codex 内置生图能力处理图片，再把结果返回网页。网页本身不持有 GPT Image API Key，也不会直接从浏览器调用 GPT Image。

目标是让用户用可视化镜位控件表达“相对原图想看到哪里”，尽量保留主体身份、风格、姿态和场景连续性。立方体只表示方向，不是三维重建或精确相机模拟；隐藏面的生成始终是模型推断。

本模块维持现有 Codex 生图路径。Workflow Canvas 的未来模型/执行方案不改变本模块；本阶段不接入 ComfyUI、不发布为任意用户登录即可生图的公网服务。

### 交互语义

- 手动模式：两个立方体使用同一主体“正面/参考方向”。原图方位角与目标方位角是用户的视觉估计；二者的最短差值用于描述移动量，目标绝对方位用于描述最终可见面。目标 `distance` 当前按近/中/远景阈值生成文字，并非经过相机几何计算的距离。
- 自动模式：上传图就是起点。水平正负号仅定义相对变化，不能从正负号直接推出一张本来带角度的图最终鼻尖朝向。`distance=1x` 表示保持原图距离，低于 1x 拉近，高于 1x 拉远。Codex 需先观察主体、头身与视线关系、空间布局及观察中心，再组织针对该图的编辑提示词。
- 不承诺像素级身份保持、精确角度或不可见结构的真实性；输出应尽量保持原图构图和比例，但当前并无强制锁定输出尺寸的执行约束。

## 3. 当前技术设计（TDD）

### 模块边界与数据流

```text
WorkbenchApp #synthesizer
  → App.tsx：上传、模式/类别/镜位、任务状态、结果和会话历史
  → CameraOrbit.tsx / Slider.tsx：镜位输入
  → services/viewPrompt.ts：手动提示词或自动任务说明
  → POST /api/jobs：Vite 本地服务保存输入图与 request.json
  → Codex 对话 + generate-view 工作流程：读取任务、分析/生成、写入结果
  → GET /api/jobs/:id：页面每 2 秒轮询
  → GET /api/jobs/:id/output：展示与下载
```

`localJobsPlugin.ts` 只注册在 Vite 开发服务中；`npm run build` 生成的静态文件不包含可独立运行的任务后端。`.view-jobs/<uuid>/` 保存 `input.<ext>`、`request.json`，完成后增加 `output.<ext>` 和 `result.json`。`scripts/view-job.mjs latest` 选最新未完成任务，`complete <id> <image-path>` 校验并登记输出文件。网页只创建/轮询任务，不直接触发生图模型。

### 任务契约

- `POST /api/jobs`：输入为图片 data URI、`mode`、`category`、目标 `camera`、可选 `sourceCamera`、提示词或自动任务说明。手动模式必须有 `sourceCamera`。返回 `{ id, status: "queued" }`。
- `GET /api/jobs/:id`：返回请求信息、`queued` 或 `complete` 状态及可用结果；`GET /api/jobs/:id/input|output` 返回图片字节。
- 服务端校验相机数值范围、类别与图片格式。请求体上限 16 MiB，解码后的图片上限 12 MiB。当前没有服务器端“失败”状态、取消、重试或任务清理 API。
- 页面任务状态为 `IDLE → UPLOADING → QUEUED → SUCCESS`，请求/轮询失败转 `ERROR`。刷新页面后 `jobId` 与会话历史不会恢复，即使磁盘任务仍存在。

### 提示词规则与测试

`services/viewPrompt.ts` 中 `shortestAzimuthDelta` 处理 ±180° 接缝；`constructPrompts` 生成手动模式中英文提示词；`constructAutoBrief` 生成待 Codex 结合原图分析的说明。`tests/viewPrompt.test.mjs` 覆盖左右方向、头部/视线、正背面、非人物类别、室内镜位、接缝和自动模式不预设原图正面。测试验证的是规则文本，不验证模型实际出图质量。

## 4. 验收与回归清单

1. 四类内容各上传至少一张图，核对输入预览不裁切、任务参数与结果显示。
2. 同一人物分别测试原图正面和原图已偏转的情况；手动模式检查角差与目标脸侧一致，自动模式检查 Codex 是否以原图为起点而非强行当正面。
3. 测试左右转向、俯仰、前后距离、±180° 接缝；角色视线不要无故回望镜头。
4. 建筑与室内场景核对结构连续性；室内不能被描述成旋转房间。
5. 覆盖非法类型/过大图片、服务不可用、任务未完成、完成后下载、浏览器刷新等状态。
6. 自动化至少运行 `npm test`、`npx tsc --noEmit`、`npm run build`；视觉质量仍需人工对比原图与结果。

## 5. 已知限制与后续决策

- **任务可靠性**：目前只有 `queued/complete`，Codex 失败或用户中断时页面可能一直等待；后续若开发任务管理，应补 `failed/cancelled`、超时、恢复与可见原因。
- **持久性**：历史、当前任务 ID 不在浏览器刷新后恢复；磁盘任务存在但没有历史索引 UI。是否做长期历史及删除策略待定。
- **距离语义**：手动模式当前是目标近/中/远景文字，自动模式是相对原图距离；未来应统一产品语义后再修改提示词和 UI。
- **复杂人物**：身体朝向与头部朝向不分别标定；复杂构图建议自动理解模式，但仍依赖模型判断。室内观察中心也由 Codex 推断，尚无用户显式选点。
- **部署边界**：当前方案限本地 Codex 开发工作流，不是网页上的免 Key GPT 登录生图服务；是否做独立打包、生产后端或多人使用另行设计。
- **视觉一致性**：立方体与角度只是意图输入；主体身份、原图比例、构图与不可见面均需以人工评估出图，不应在文档或 UI 中承诺精确三维重建。
