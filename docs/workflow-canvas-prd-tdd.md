# Workflow Canvas — PRD + TDD

> 基线日期：2026-10-03。本文将 PR 理解为产品需求（PRD），与技术设计（TDD）合并记录。状态严格区分“可交互的画布”与“真正执行模型的工作流”。

## 1. 定位与边界（PRD）

Workflow Canvas 是 Codex Workbench 中独立的无限画布节点工具，复用早期 FLOWNODE 原型的深色卡片和拖拽交互，背景使用低对比度灰点。它与 View Synthesizer 并列，不把视角转换器嵌进画布；两个模块通过顶栏切换，切换时暂不卸载组件。

当前交付目标是**本地工作流编辑器的基础交互**：创建文本、GPT Text 和 Image 节点，编辑文本，连接有类型的端口，并保存画布。AI 文生文和生图执行仍是占位；不得把占位预览描述成模型输出。本阶段不包含视频节点，也不实施此前讨论的 ComfyUI 接入方案。未来使用何种模型/授权/执行通道尚未决定。

当前节点类型和端口：

| 节点 | 输入 | 输出 | 现阶段真实数据 |
| --- | --- | --- | --- |
| Text Input | 无 | `Text: text` | 用户输入的本地文本。 |
| GPT Text | `Prompt: text`、`Context: text` | `Text: text` | 指令和普通文本上游预览；输出为空/未执行。 |
| Image | `Prompt: text`、`Reference: image` | `Image: image` | 占位卡片及文本连接数；无图像资产。 |

“多上游”目前是**连接能力**，不是已定义的输入合并语义。多个边进入同一端口时，未来如何排序、拼接、覆盖或让用户选择，必须在执行功能开发前明确。

## 3. 当前技术设计（TDD）

### 模块边界与状态

```text
WorkbenchApp #workflow
  → WorkflowPage.tsx：画布视图、节点/连线交互、编辑栏、缩放/平移、localStorage
  → workflow/graph.ts：Node/Edge/Port 类型、初始示例图、连线规则、直接上游文本查询
  → workflow/workflow.css：FLOWNODE 风格及灰点画布
```

`WorkflowGraph = { nodes, edges }`。节点含 `id/kind/x/y/title/content`，边含 `id/fromNodeId/fromPort/toNodeId/toPort`。端口在 `PORTS` 中声明，值类型为 `text` 或 `image`。图存于浏览器 `localStorage` 键 `codex-workbench-workflow-v3`；选中节点、平移和缩放只在组件内存中，不随刷新恢复。新增节点使用 UUID，画布坐标是缩放/平移前的世界坐标。

连接规则由 `connectionError` 负责：在允许一对多、多对一的同时拒绝自环、重复同端口对、类型错误和循环。因此当前图是有向无环图（DAG）的编辑目标，但加载历史数据时 `isWorkflowGraph` 主要检查形状和节点引用，**不会重新验证每条边的端口类型或无环性**。

`incomingText` 只读取**直接连接的 Text Input 节点**；不会递归解析 GPT Text 的输出。当前 `GPT Text`、`Image` 不存在运行态、产物对象、调度器、后端任务或真实数据传递。Image 的 `Reference` 端口仅是将来可接 `image` 类型边的图结构声明。

### 编辑器交互

- 指针按下标题并移动：更新节点世界坐标；指针按下空白画布：更新平移。端口连线在释放指针时根据目标输入端口判断是否合法。
- 连线用 SVG 贝塞尔曲线渲染；拖动时显示临时曲线。端口和节点用 CSS 承担命中与视觉反馈。
- 缩放按当前视口/鼠标位置调整，范围 0.45～1.8；按钮可缩放或回到默认视角。
- 页面带示例 Text→GPT Text 与 Text→Image 的扇出图，说明“一源多下游”。示例 Image 节点仍只是占位。
- 保存采用每次图状态变化后写入 `localStorage`。重置会覆盖当前本地画布，UI 使用确认对话框；没有撤销或回收站。

## 4. 后续执行设计的约束（非本期实现承诺）

若将来要让 GPT Text 或 Image 真正运行，建议先确定以下契约，再选择供应方或本地引擎：

1. **执行输入**：每种输入端口的多边语义、空输入行为、参数来源、上游版本与执行顺序。执行时只消费上游已完成的产物，而非直接读取 UI 文本预览。
2. **运行状态**：`idle/queued/running/succeeded/failed/cancelled`、任务 ID、错误详情、重试/取消与失败后的下游行为。DAG 可按依赖拓扑顺序执行，但应能只重跑受影响的分支。
3. **产物类型**：文本与图片作为独立资产/结果记录，包含来源节点、输入快照、模型/工作流版本与生成时间。不要把大图片 data URI 塞入现有 `localStorage` 图 JSON。
4. **执行器边界**：前端图与模型实现分离；接口负责提交、进度、产物获取。使用 Codex 对话、本地服务、云 API 或其他方式均应是明确选择，不能从占位端口推断已具备“浏览器无 Key 直接调用 GPT”的能力。
5. **保存与迁移**：若引入多画布、导入导出、长期历史或服务器资产，需要图 schema 版本与迁移策略；不能直接复用当前 `v3` localStorage 作为长期数据库。

此前讨论的本地 ComfyUI 路线现已暂缓，**不是**本期默认执行方案。视角转换器继续独立使用既有 Codex 生图流程。

## 5. 验收与回归清单

### 当前编辑器基线

1. 在两个模块间来回切换，确认各自页面状态不因切换丢失。
2. 新增三种节点、拖动节点、平移/缩放画布、修改 Text/GPT Text 文本，刷新后图数据恢复。
3. 测试 Text→多个下游，以及多个 Text→同一 GPT Text 输入端口；上游预览随直接文本变化而更新。
4. 测试错类型、自连接、重复连接和成环时不会添加边；删除节点后相关边同步消失。
5. 重置操作需用户确认；取消不改变图，确认后恢复示例图。
6. 运行 `npm test`、`npx tsc --noEmit`、`npm run build`；再做指针拖拽、端口命中和不同屏幕尺寸的手工浏览器验证。现有 `tests/workflowGraph.test.mjs` 只覆盖图规则，不覆盖浏览器手势或持久化。

### 将来执行版需另行验收

模型实际运行、进度与错误、上游产物传递、参考图处理、重试/取消、持久化和模型费用/权限，均不能以当前占位节点的 UI 验收替代。

## 6. 已知限制与待定决策

- 暂无单条连线删除/改线、撤销重做、键盘快捷键、图导入导出、多画布管理或协作。
- `localStorage` 是单浏览器单键保存；清理站点数据会丢失图，重置也没有恢复点。
- 新节点生成于视口中心附近，可能与现有节点重叠；大图性能、触屏与可访问性尚未系统验证。
- `incomingText` 不读取 GPT Text 产物；在执行引擎设计前，不能把连通的 GPT Text→Image 理解为已可运行的数据链。
- 多上游汇聚规则、图片资产存储、默认模型/执行通道、工作流保存粒度及错误传播语义仍待产品决策。
